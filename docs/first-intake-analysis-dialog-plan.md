# Первый приём (Анализ): план переделки раздела самоанализа

Дата: 2026-06-18  
Репозиторий: `andylitvinov-design/report`

## 1. Цель задачи

Переделать раздел **«Самоанализ» / «Сделать самоанализ»** в раздел **«Первый приём (Анализ)»**.

Новая логика: пользователь не заполняет сухую анкету, а проходит мягкий первичный диалог, похожий на общение с терапевтом. Экран должен вести пользователя через несколько коротких вопросов, помогать прояснить текущее состояние и в конце показывать предварительное понимание.

Важно: это не медицинская диагностика, не назначение лечения и не обещание результата. Формулировки должны быть безопасными: «прояснить», «рабочая гипотеза», «поддержка», «требует проверки», «материал для специалиста».

## 2. Что нужно найти в коде перед изменениями

Перед реализацией Codex должен найти фактический экран из скриншота по текстам:

```txt
Сделать самоанализ
Начать самоанализ
Самоанализ
Комментарий специалиста
Запросить отчёт
Подготовьте новый срез без лишнего шума
```

Если поиск по текстам не находит экран, искать по визуально связанным компонентам / маршрутам:

```txt
Holistic Therapy Cabinet
Профиль / Обзор
Отчёт эксперта
Назначение
Рекомендации
```

После нахождения компонента не создавать параллельный дублирующий экран, а переделать именно текущий раздел.


Этот пункт должен быть в верхней части меню, сразу после `Профиль / Обзор`, и оставаться активным в текущем стиле.

### 3.2. Верхний hero-блок

```txt
Первый приём (Анализ)
```

Eyebrow:


Подзаголовок:

```txt
Анна / ID C-1024 · Фокус: Здоровье / тело · Первый диалог для прояснения текущего состояния
```

Главная кнопка:

```txt
Начать первый приём
```

## 4. Центральная карточка

Название карточки:

```txt
Первый приём
```

Заголовок:

```txt
Давайте спокойно проясним, что с вами сейчас происходит
```

Описание:

```txt
Я задам несколько коротких вопросов. Отвечайте не идеально, а как есть сейчас. Нам важно поймать текущее состояние, главный узел и то, что сейчас требует поддержки.
```

Ниже должно быть окно общения: реплика терапевта, выбранные ответы пользователя и варианты следующего ответа.

## 5. Сценарий диалога

Диалог идёт пошагово. На каждом шаге показывать:

- индикатор `Шаг X из 6`;
- реплику терапевта;
- варианты ответов кнопками;
- необязательное поле `Добавить своими словами`;
- кнопку `Назад`, если это не первый шаг.

### Шаг 1 — главный фокус

Реплика:

```txt
Смотрю на вашу текущую ситуацию. С чего лучше начать: что сейчас сильнее всего беспокоит?
```

Варианты:

```txt
Физическое состояние / симптомы
Эмоции и тревога
Усталость / нет сил
Отношения / контакт с людьми
Работа / деньги / реализация
Не понимаю, что происходит
```

Поле данных: `mainConcern`.

### Шаг 2 — где ощущается

Реплика:

```txt
Где это сейчас ощущается сильнее всего?
```

Варианты:

```txt
Голова / напряжение
Грудь / дыхание
Живот / пищеварение
Кожа / воспаление
Общая слабость
В отношениях / контакте
В мыслях / невозможности решить
Другое
```

Поле данных: `feltArea`.

### Шаг 3 — сила состояния

Реплика:

```txt
Насколько это сейчас сильно, если смотреть честно по последним дням?
```

Варианты:

```txt
1–3: слабо, но заметно
4–6: мешает жить
7–8: сильно захватывает
9–10: почти невозможно выдерживать
```

Поле данных: `intensity`.

### Шаг 4 — что усиливает

Реплика:

```txt
Что обычно усиливает это состояние?
```

Варианты:

```txt
Стресс / спешка
Конфликт / давление
Одиночество
Усталость / недосып
Страх оценки
Неопределённость
Не знаю
```

Поле данных: `trigger`.

### Шаг 5 — что облегчает

Реплика:

```txt
Что хотя бы немного облегчает состояние?
```

Варианты:

```txt
Отдых
Поддержка другого человека
Тепло / тело / прикосновение
Понимание причины
Природа / прогулка
Структура и план
Пока ничего
```

Поле данных: `relief`.

### Шаг 6 — желаемый результат

Реплика:

```txt
Что было бы самым полезным результатом первого приёма?
```

Варианты:

```txt
Понять главную причину состояния
Получить короткий план поддержки
Понять, какой отчёт нужен специалисту
Определить, что проверить дальше
Собрать состояние в ясную картину
```

Поле данных: `desiredOutcome`.

## 6. Финальный экран

После 6-го шага показать блок:

Заголовок:

```txt
Предварительное понимание
```

Текст:

```txt
Сейчас видно несколько важных точек:
1. где находится главный дискомфорт;
2. что его усиливает;
3. что даёт хотя бы небольшое облегчение;
4. какой результат первого анализа для вас сейчас важнее всего.

На основе этого можно подготовить первичный отчёт специалиста. Это не медицинский диагноз, а рабочая карта текущего состояния для дальнейшего прояснения.
```

Кнопки:

```txt
Запросить отчёт специалиста
Продолжить уточнение
Сохранить как черновик
Начать заново
```


## 8. Локальная модель состояния

На первом этапе достаточно локального состояния без Supabase.

```js
const FIRST_INTAKE_INITIAL_ANSWERS = {
  mainConcern: "",
  feltArea: "",
  intensity: "",
  trigger: "",
  relief: "",
  desiredOutcome: "",
  notes: {}
};
```

Состояния:

```js
const [currentStep, setCurrentStep] = useState(0);
const [answers, setAnswers] = useState(FIRST_INTAKE_INITIAL_ANSWERS);
const [isStarted, setIsStarted] = useState(false);
const [isComplete, setIsComplete] = useState(false);
```

После выбора ответа:

```js
setAnswers((current) => ({ ...current, [step.id]: option }));
```

Если это не последний шаг — перейти дальше. Если последний — показать `isComplete`.

## 9. Визуальная логика

Сохранить текущую эстетику:

- тёплый светлый фон;
- крупные скруглённые карточки;
- зелёные основные кнопки;
- мягкие бежевые рамки;
- крупный serif-заголовок;
- живой терапевтический тон.

Добавить ощущение чата:

- пузырь терапевта;
- маленькие пузырьки выбранных ответов пользователя;
- варианты ответа как кнопки-чипы;
- мягкий прогресс `Шаг X из 6`.

## 10. Безопасные и запрещённые формулировки

Можно:

```txt
прояснить состояние
рабочая гипотеза
требует проверки
направление поддержки
материал для специалиста
может быть полезно
```

Нельзя:

```txt
диагноз
вылечим
гарантируем результат
назначаем лечение
отмените лечение
медицинское заключение
```

## 11. Проверки

После реализации запустить доступные проверки проекта. Минимально:

```bash
npm run build
```

Если в проекте есть delivery/test scripts, запустить их тоже:

```bash
npm run delivery:check
npm run test
```

Если конкретной команды нет, указать это в финальном отчёте и показать, какие проверки реально были доступны.

## 12. Критерий готовности

Готово, если:

1. Раздел называется `Первый приём (Анализ)`.
2. Верхняя кнопка называется `Начать первый приём`.
3. Центральная карточка выглядит как диалог с терапевтом.
4. Есть 6 шагов вопросов.
5. Выбор ответа переводит на следующий шаг без перезагрузки.
6. Есть `Назад`, `Начать заново`, финальный блок `Предварительное понимание`.
7. Правая колонка объясняет, как отвечать.
8. Нет медицинских диагнозов и обещаний лечения.
9. Существующие разделы кабинета не сломаны.
10. Проверки проекта проходят или явно указан внешний блокер.
